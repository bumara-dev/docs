1. Background
The Zambia Union of Government and Allied Workers provides member incentives
including:

Baby hampers
Funeral hampers
Education loans
Education hampers
Applications are submitted via a website, and incentives are distributed physically or
financially.

2. Key Challenges Identified
2.1 Lack of System Integration
Current website is not integrated with any backend system
Applications submitted online:
o Are not automatically captured in a central system
o Require manual handling and tracking
Result:
o Inefficiencies
o Risk of lost or unprocessed applications
2.2 Poor Application Tracking
No centralized system to:
o Track which member applied for what
o Track approval status of applications
Difficult to generate:
o Application reports
o Status updates
2.3 Inventory Management Gaps
No system to track:
o Merchandise stock levels (e.g. hampers)
o Distribution by district
o Which member received which item
Current process is manual, leading to:
o Poor accountability
o Inability to reconcile stock vs distribution
2.4 Disconnection Between Applications and Inventory
No linkage between:
o Applications submitted
o Inventory available
o Items distributed
Result:
o Difficult to match:
▪ Requests vs fulfilment
▪ Stock vs allocations
2.5 Financial Tracking Issues (Accounts Department)
Accounts team is responsible for:
o Processing payments (e.g. education loans)
Current gaps:
o No system to show:
▪ Who has been paid
▪ Who is pending payment
▪ Payment status linked to applications
Requires manual reconciliation between:
o Admin approvals
o Payment execution
2.6 Lack of Role-Based Access / Departmental Views
No structured system for:
o Admin team
o Accounts team
o Other departments
Need for:
o Separate dashboards/panels
o But within an integrated system
2.7 Reporting Limitations
No automated reporting system for:
o Applications received
o Approvals vs rejections
o Inventory distribution
o Payments made
Need for:
o Descriptive and summary reports
o Possibly exportable (Excel/PDF)
3. Proposed System Requirements
3.1 Integrated Application Management System
Website should be integrated with backend system to:
o Automatically capture applications
o Store member data
o Track application status (submitted → approved → fulfilled)
3.2 Inventory Management Module
Track:
o Stock levels per item (e.g. hampers)
o Distribution by district
o Allocation to individual members
Should allow:
o Real-time updates
o Stock reconciliation
3.3 Application-to-Fulfilment Linkage
Each application should:
o Be linked to:
▪ Inventory (if physical item)
▪ Payment (if financial support)
System should show:
o Application → Approval → Fulfilment status  
3.4 Financial Management (Accounts Panel)
Dedicated Accounts Dashboard
Features:    
o View approved applications requiring payment
o Update payment status (Paid / Pending / Rejected)
o Track disbursements
3.5 Role-Based Access Control
Different system panels for:
o Admin Team
▪ Review and approve applications
o Accounts Team
▪ Manage payments
o Supervisory/Management
▪ View reports and analytics
All panels must be:
o Integrated within one system
o Access-controlled
3.6 Reporting & Analytics
System should generate:

Application reports:
o Total applications by type
o Approval rates
Inventory reports:
o Stock levels
o Distribution by district
Financial reports:
o Payments made vs pending
Export options:
o Excel / PDF
4. Key Outcome Expected
A centralized, integrated system that:

Eliminates manual processes
Improves accountability
Links applications, inventory, and payments
Enables real-time tracking and reporting across departments
