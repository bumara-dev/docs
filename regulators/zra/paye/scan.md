## 0. Executive Summary

### ✅ Already Implemented (Comprehensive!)

1. **Full PAYE Submissions API** — Complete CRUD at `/zra/paye/submissions/*`:
   - `POST /zra/paye/submissions` — Create with employees
   - `GET /zra/paye/submissions` — List for org
   - `GET /zra/paye/submissions/:id` — Get with employees
   - `PATCH /zra/paye/submissions/:id/status` — Status transitions
   - Employee CRUD: Add/Update/Delete employees
   - `GET /zra/paye/prefill-data` — Prefill from previous period

2. **Data Model** — `paye_submissions` + `paye_employees` tables:
   - Uses `decimal(15,2)` for all money ✅
   - Auto-calculates totals from employees
   - Generates reference numbers (`ZRAPAYE-2026-01-XXXXX`)
   - Calculates deadlines (10th of following month)
   - Nil return support with reasons

3. **Status Flow** — `draft` → `pending` → `processing` → `accepted`/`rejected`/`late`/`amended`

4. **Audit Logging** — All CRUD operations log to audit with sanitization

5. **Org Scoping** — All services use `requireOrganizationContext(ctx)` ✅

6. **General Infrastructure**:
   - `submission_jobs` + `submission_gate_snapshots` tables
   - `requestSubmission()` service with readiness checks
   - `payment_requests` table (cents-based) + verification
   - `documents` table with `kind` enum

### ⚠️ Integration Gaps

1. **No Link to Compliance Filings** — `paye_submissions` is standalone; no `filingId` column
2. **No Task Integration** — PAYE completion doesn't trigger task completion
3. **No Submission Job Integration** — Can't request Bumara to submit via backoffice flow
4. **No Tenant Filings UI** — Existing `/regulators/zra/filings/[filingId]` doesn't show PAYE form
5. **No Backoffice PAYE Processing UI** — Need evidence upload + guards

### 1.3 Current Gap: No Link to Filings Table

The `paye_submissions` table is standalone. For the compliance workflow:
- Filings come from `filings` table (generated by activation engine)
- PAYE data figures need to be captured for backoffice submission

**Options:**
A) Add `filingId` to `paye_submissions` to link them
B) Store simplified PAYE figures in `filing_payloads` or tasks payload
C) Store in a new `zra_paye_filing_data` table linked to filings

**Recommendation:** Option A — Add `filingId` to `paye_submissions` and reuse existing employee-level structure.

## 9. Implementation Approach

### 9.1 Data Model Strategy

**Chosen approach:** Link `paye_submissions` to `filings` via new `filingId` column

This allows:
- Reuse of existing PAYE employee-level structure
- Link to compliance workflow (tasks, docs, submissions)
- Keep detailed employee data for backoffice review

### 9.2 Task Template for PAYE Filing

```typescript
taskTemplateConfigs: [
  { key: 'enter_paye_figures', title: 'Enter PAYE Figures', taskType: 'fill_form', required: true, sequence: 1 },
  { key: 'upload_payroll_summary', title: 'Upload Payroll Summary', taskType: 'upload_document', required: true, sequence: 2 },
  { key: 'review_confirm', title: 'Review and Confirm', taskType: 'review_approve', required: true, sequence: 3 },
]
```

### 9.3 Auto-Completion Rules

- Saving valid PAYE figures → marks `enter_paye_figures` task DONE
- Uploading doc with `requirementKey='payroll_summary'` → marks `upload_payroll_summary` task DONE
- Confirmation checkbox → marks `review_confirm` task DONE

### 9.4 Readiness Gates

Filing is `READY_FOR_SUBMISSION` when:
1. All required tasks DONE (or skipped with reason)
2. All required docs uploaded
3. PAYE figures saved (non-nil OR nil with reason)

### 9.5 Submission Flow

1. Tenant clicks "Request Submission"
2. `requestSubmission()` checks readiness, creates job + snapshot
3. If payment required: create `payment_requests` + `tickets` (PAYMENT_REQUEST type)
4. Job enters backoffice queue

### 9.6 Backoffice Flow

1. Agent claims job (QUEUED → ASSIGNED)
2. Agent starts work (ASSIGNED → IN_PROGRESS)
3. Agent submits to ZRA portal manually, uploads SUBMISSION evidence
4. Mark filing SUBMITTED (requires SUBMISSION evidence)
5. ZRA accepts/rejects
6. If accepted: upload CERTIFICATE evidence, mark filing ACCEPTED
7. Job closes
